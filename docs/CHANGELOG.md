# 更新记录

## 0.2.10

- **同一条正文被投递多次（「自动注入 3 次」复发）**：调用方超时重试 / 连点 / 多标签页同时触发时，
  同一段正文会被投进桥会话多次，模型把同一段剧情写好几遍提示词。现在 `/api/ask` 与
  `tavern/ask` 共用一道去重闸门：按「会话 + 正文指纹」记 10 分钟——
  - 上一笔还在投递中 → `409 {"code":"duplicate"}`，不再注入；
  - 刚投递成功（10 分钟内）→ 直接返回上次结果并带 `duplicate:true`；
  - 投递失败自动释放，可以立刻重试。
- **「只收到时间信息，没收到正文」再次复发（这次是历史残留顺序）**：`@deepseek-ai/dsh-time-context`
  的时间行是一条**独立的 user 消息**，排在我们正文之后。0.2.7 只在**当次请求**里把它挪到正文前面，
  会话里两条消息的先后没变；模型下一步回头看历史，最后一条 user 消息仍然是时间戳，于是又回
  「这一轮只收到了时间信息」。现在 `agent/pre-step` 里把时间行**折进正文**（正文在前、时间在最后并
  带「不是用户输入」的说明），只提交一条 user 消息，历史里不再单独躺着时间戳。
- `tavern/info` 补一句 `delivery: "request-session-id"`，并把 DSH 侧默认值改叫
  `defaultTarget` / `defaultSource`（旧字段 `target` / `source` 保留兼容）：酒馆投递的会话由
  请求体 `sessionId` 决定，这两个默认值只影响 DSH 前端自己的「投递」按钮和自动捕获。
- 新增覆盖：时间注入折叠（3 条断言）、重复投递保护（两次同文返回缓存 + 不同正文正常投递）、
  `info` 的新字段与兼容字段。主机测试 517 → 534。

- **新增 `/__airp_comfy/tavern/*` 跨源入口**，给酒馆助手插件用：酒馆页面在另一个端口，
  既过不了 `requireSameOrigin` 的同源闸门、也拿不到没有 CORS 头的响应，于是单独开一条通道。
  - `GET tavern/ping` 探活；`GET tavern/info` 看当前 target/source 摘要与 routePath；
  - `GET tavern/sessions` 本机会话列表（`?limit=1..500`，只带选会话需要的字段：
    `sessionId` / `title` / `displayTitle` / `updatedAt` / `running` / `live`，
    同名会话再带 `firstText` / `userCount`）；
  - `POST tavern/ask` 投递正文并等桥会话回复，内部**直接复用 `handleAsk()`**，语义与 `/api/ask` 完全一致；
  - 鉴权沿用已有的 `x-prompt-relay-token`（`source.token` / `target.token`）；
    `info` / `sessions` 也走同一道闸门（没配口令时本来就不拦，零摩擦）。
  - **没有改动任何既有路由、`requireSameOrigin`、`handleAsk` 或前端代码**，只是外面加了一薄层。
- **跨源白名单默认收窄**：不再放行「同机任意端口」。`tavern.origin` 为空时只认
  `http://localhost:8080` 与 `http://127.0.0.1:8080`（酒馆默认端口）；需要别的端口 / 来源就配
  `tavern.origin`（多条用逗号或空格分隔）；`https` 来源也不再默认放行。
- `tavern/ping` / `info` / `sessions` 只认 GET（其余 405）；预检
  `Access-Control-Max-Age` 从 600 降到 60，改完白名单不用等 10 分钟。
- 文档：[`docs/TAVERN_CHANNEL.md`](TAVERN_CHANNEL.md)（路由、**`sessionId` 用 `target`** 的约定、
  错误码表、调试 curl、已知边界）。
- 新增 32 条 HTTP 层测试：预检 / CORS / 外站 403 / 默认白名单收窄 / ping 方法 /
  info 与 sessions 的口令闸门 / 多来源配置归一化。主机测试 485 → 517 全绿。

## 0.2.8

- **修「概览一直读取 / 工作流空白 / 图库一直加载 / 打开侧边栏后页面刷不动」**：这不是插件冲突，是浏览器连接池被事件流占满了。
  - 浏览器对同一个源的 HTTP/1.1 连接数有上限（Chromium 默认 6 条）。本插件之前是**悬浮球一条 `EventSource`、右侧栏每个实例再一条**，会话标签一多就线性叠加；再叠上其它插件的常驻事件流，6 条很快被长连接占光。
  - 连接池一满，新的普通请求（概览 / 图库要的 `state`、工作流的 `config`）只能一直排队，**连刷新页面的导航请求都排不进去**——表现为所有面板一直转圈、新开标签页永远卡死。本插件 fetch 的 20 秒超时最后会弹一句 `signal is aborted without reason`，就是排队超时的报错文本。
  - 现在整个页面**共用一条 `/events`**：第一个订阅者建立连接，最后一个卸载时才关闭；组件侧仍是 EventSource 的写法（`addEventListener` / `onopen` / `onerror` / `close`）。本插件占用的连接数从「N 条」降到 **1 条**。
- 新增 3 条客户端结构性测试：整个客户端只允许出现一次 `new EventSource`、两个席位都走共享连接、最后一个订阅者卸载才关闭。

## 0.2.7

- **修「只收到时间戳、正文没跟着来」（这次是根因）**：宿主的 `@deepseek-ai/dsh-time-context` 每 10 分钟左右会在模型请求前再补一条只有三行的用户消息，并且**排在我们投递的正文后面**。模型看到「最新一条用户消息是时间戳」，就以为这一轮只收到了时间戳，于是回一句「正文没跟着来」——正文其实就在上一条，它甚至能复述内容。现在两处一起兜：
  - 桥会在 `agent/pre-step` 里把这条时间注入挪到正文**前面**（只动我们自己投递的那一轮，不影响你平时的对话），模型看到的最后一条用户消息始终是正文；日志里会写「时间注入排在正文后面，已挪到正文前」。
  - 桥消息末尾附一句说明：「本条之后若还有一条只写着 Time sampled… 的自动时间标记，那不是用户输入」。万一排序钩子因为插件加载顺序没生效，模型也不会把正文当成没到（这句说明放在用户自己的「附加消息（最下面）」之前，附加消息仍然是最下面）。
- **投递结果可核对**：之前 `user/message` 的负载本身就带 `content`，代码却只读 `payload.message`，所以「这一轮有没有看到投递的正文」永远判成 false（远程任务里的 `deliveryMode` 也没传回来）。现在能正确判断：看到正文记 info，没看到记 warn 并在任务上加⚠；远程投递也会把 `deliveryMode` / `idleWaited` 带回来。
- **「只有人物卡开场」不再当正文**：Tavern 把人物卡开场种成会话的第一条助手消息。选错会话（同一角色的会话标题都一样）或刚开的会话，以前会把开场白投出去。现在：
  - 自动捕获遇到「整个会话只有一条助手消息、且前面没有真人消息」时会跳过并记一条 warn；
  - 手动投递 / 重新生成会直接拒绝，提示「这个会话里只有人物卡开场」；
  - 概览的正文框在读到这种会话时给一句提示。
- **同名会话能区分了**：Tavern 里一个角色就是一个目录，所有会话标题都叫「沐白形象管理」。设置页的会话下拉现在对**标题重复**的会话补上「首条用户消息 + 条数」（例如 `沐白形象管理 · “小欣，别紧张…” · 83条`），鼠标悬停还能看到完整首条和会话 id。标题唯一的普通会话保持原样。

## 0.2.6

- **单击图片框亮出所有菜单**：在图片上单击一下，四角按钮（固定左侧 / 悬浮左侧 / 右侧栏看图 / 收起）和左下角铅笔展开的那排菜单会一起出现，不用先把鼠标挪到角上。
  - 亮起来之后，框里只要还有操作（移动、点击、滚轮、捏合、点菜单）就一直续着；**5 秒没有操作自动收回**，回到原来的「鼠标靠近角落才出现」。
  - 手动再点一下铅笔把菜单关掉会立刻收回，不用等 5 秒。
  - 双击收起图片框不会先闪一层菜单（第二下点击会撤掉待亮的菜单）。
- **支持双指捏合缩放**：触屏 / 触控板上两指捏合可以放大缩小图片框（之前只认滚轮）。
  - 以两指中点为中心缩放，捏合时两指一起移动就跟着平移。
  - 缩放范围和滚轮完全一致（不会小于 280×360，也不会超出视口）；停靠在左侧时捏合调的是停靠宽度。
  - 两根手指都在图片框里才接管，框外双指缩放还是缩放页面。
  - 捏合期间不会误拖动图片框，捏合结束才写本地存储。

## 0.2.5

- **修「只收到时间戳、正文没跟着来」**：自动投递前先等目标会话空闲（最多 15 秒）。有些宿主（例如带自动续写的 Tavern）会让会话一直有事在跑，这时 `queue` 投递的正文会被排到下一轮，而当前这一轮模型只看到时间上下文注入的那三行。
- 等不到空闲就改用 `steer`，把正文塞进正在跑的这一轮，至少模型能看到内容；任务记录里新增 `deliveryMode` 字段，日志里也会写「目标会话忙，正文改用 steer 投递」。
- 顺带在任务 / 日志里带上等待时长，方便判断是不是宿主一直在忙。

## 0.2.4

- **纯黑图误判修复**：判定前先看体积——真·纯黑 PNG 只有 20 多 KB，超过 **120 KB** 的图直接不参与判定。之前有正常图（约 1 MB）在「原地替换后立刻复查」时被判成黑图，导致同一张图被连续替换 3 次。
- **判黑要两次都黑**：第一次判黑后会隔 0.9 秒、绕过浏览器缓存再验一次，两次都黑才自动替换，避免一次绘制的偶发全黑。
- **判定可追溯**：每次判定都会把统计（体积、暗像素比例、平均亮度、亮点比例、不透明覆盖）写进 Host 日志，「日志」页能直接看到；出现误判时能一眼定位是哪条规则触发。

## 0.2.3

- **自动补图可以随时停下**：补图进行中，图片框左下菜单的按钮会变成「终止」（之前因为补图是内部任务，菜单里根本看不到它），点一下清空队列并中止正在跑的那一单；全屏和工作台的「终止」也一样。右侧栏顶部还有一条「停止自动补图」。下一次新任务开始时自动复位。
- **黑图自动替换开关**：工作流页 →「图片输出相关」→「额外设置」里新增开关，关掉后不再检测纯黑图，待补队列也会清空。
- **纯黑判定更严，修掉误判**：以前只要求「暗像素 ≥ 99%」就会判黑，夜景、黑底小主体这类图会被误伤。现在必须同时满足：暗像素 ≥ 99.5%、平均亮度 ≤ 8、亮点（亮度 > 110）占比 < 0.1%，并且不透明像素要占到一半以上（透明底的小图不算黑）。
- **固定种子可手填**：工作流页「每次换随机种子」下面多了一个「固定种子」输入框。
  - 勾着自动时它是灰的，显示**上一轮实际用的种子**（方便看到满意的一张后直接固定下来）；
  - 取消勾选后解锁，填的整数会立刻存进工作流，出图时覆盖每一处字面量 seed；取消的那一刻会把上一轮的种子自动带进来。
  - 这些开关改完直接生效，不用再点「保存」。


## 0.2.2

- **LoRA 强度可以填负数**：工作台「连续图」的档位、LoRA 页每条的强度都允许 `-5 ~ 5`（反相 LoRA 用）。

## 0.2.1 — 首个公开发布

第一个放到 npm / 插件市场里的版本，功能面就是 README 里描述的这一整套：

- **自动出图**：捕获会话正文 → 投递到提示词会话 → 按规则切分 → 调本地 ComfyUI 出图 → 归档回 DSH。「自动投递正文」「自动出图」可分别开关，悬浮球 **A** 是总开关。
- **投递与来源**：正文来源与提示词来源分开设置，默认跟随当前会话，也可指向本进程或另一台 DSH 的会话；概览里的正文框默认留空，手写内容只在点「投递最新正文」时优先使用；附加消息可放正文最上面或最下面，投递成功后自动留空。
- **看图**：右侧栏面板、全屏看图、悬浮球、悬浮图片框。翻页、页码、下载、收藏、刷新、删除、圆角切换；删除当前图优先停到下一张；全屏与悬浮框的切图状态同步，切标签再回来位置不变。
- **跟图**：滚动正文自动切图、连续图按段落比例拆位置、光标跟图、手动偏移、清空定位。
- **工作台**：内置格式 / 全部匹配 / 自定义标签三种提示词方式；多套正负面、标题、原文锚点、分辨率；连续图、LoRA、随机种子、输出节点裁剪。
- **图库**：当前会话 / 全部 / 收藏夹 / 回收站，每页 9 张三列，收藏是复制副本。
- **工作流与 LoRA**：导入 ComfyUI API JSON、占位符与节点映射、解析预览、干跑；LoRA 堆 / 单 LoRA / Power / Stacker / Tag，可改名、调强度、保存到工作流。
- **界面**：日间 / 夜间、窄栏布局、轻提示、出图完成提示。
- **安装**：`dsh plugin --profile web add dsh-comfyui-rp`；本地目录开发用 `node tools/install.mjs --apply`。需要本地 ComfyUI，适用于 DSH 0.2.x。
